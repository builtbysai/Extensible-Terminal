# Known limitations

- `terminal-cli` uses a real raw-mode terminal-emulation path and now keeps one geometry-bounded snapshot of the last rendered grid. Ordinary output emits only cells whose bounded `Cell` value changed plus cursor/visibility updates; first render and host resize intentionally clear and redraw the full surface. Wide-cell continuation slots are never emitted over their base glyph, while transitions from a former continuation back to a normal cell are explicitly redrawn. A deterministic 80x24 renderer regression measures a one-cell update as 1 emitted cell versus 1,920 cells for a full redraw. The cache still compares the current surface against the last rendered snapshot, so this is an output/damage reduction rather than a claim of constant-time rendering or a universal latency budget.
- Release compatibility coverage now exercises representative full-screen traffic in combined sequences rather than only isolated parser cases: alternate-screen entry/exit, DECSTBM/DECOM, DECAWM, cursor save/restore, SGR/BCE, application cursor/keypad modes, bracketed-paste negotiation, resize, repeated screen switching, high-rate output, bounded scrollback, and slow-extension backpressure. Ubuntu CI additionally drives the production frontend through a real local `less` pager session. Windows retains the dedicated ConPTY frontend smoke but does not claim an equivalent built-in pager integration.
- CI records a non-gating terminal-core feed-throughput sample and fixed cell/grid/scrollback storage bounds. Shared-runner wall-clock throughput is intentionally informational rather than a pass/fail latency budget. The representative 80x24 bounded-resource regression keeps 512 scrollback rows under a fixed cell-storage ceiling and verifies the runtime never retains more than the configured scrollback row count.
- The VT parser remains intentionally incomplete. It supports common cursor movement, erase/edit operations, DECSTBM scroll margins, primary/alternate screens, cursor visibility, DECAWM auto-wrap negotiation, indexed and direct-RGB SGR colors, bounded scrollback, incremental UTF-8 decoding, resize preservation, ANSI/DEC status replies, primary device attributes, bounded configurable horizontal tab stops, DECCKM application cursor keys, DECKPAM/DECKPNM application keypad negotiation, bracketed-paste negotiation, bounded xterm mouse event-selection observation, and streaming consumption of unsupported OSC/DCS/SOS/PM/APC control strings. OSC payloads are ignored through BEL or ST; the other supported string introducers are ignored through ST so unsupported metadata cannot leak into rendered text. Public CSI observation remains fixed at 16 parameters: sequences exceeding that bound are consumed through their final byte and discarded rather than partially executed. Syntactically well-formed CSI parameter/intermediate forms that this terminal does not implement are likewise consumed through the CSI final rather than leaking unsupported control finals into rendered text; this consumption is not a claim that those commands are supported.
- Terminal stream finalization is explicit. If a PTY/ConPTY stream ends with an incomplete UTF-8 scalar, the terminal emits exactly one U+FFFD using the existing cell/style rules before final rendering. Incomplete ESC, CSI, and control-string state is cancelled at end of stream without executing a partial control or leaking retained payload text. This is a decoder/parser completion rule only; it does not synthesize output for an already complete stream.
- RIS (`ESC c`) restores the complete state implemented by this terminal for the current geometry and configured scrollback bound: primary/alternate screen selection and contents, cursor/saved cursor, scroll margins, SGR, DECOM/DECAWM, application cursor/keypad and bracketed-paste modes, mouse negotiation, configurable tab stops, and retained scrollback return to their initial values. It does not reset or replace endpoint transport ownership, SSH/tmux lifecycle, or host terminal configuration.
- DECSC/DECRC cursor save/restore and the `?1049` alternate-screen path preserve the implemented cursor position, graphic rendition, and DECOM origin-mode state. Restored absolute rows are clamped to the active vertical bounds if scroll margins changed after the save. This is deliberately not a claim of complete VT220 DECSC state: character-set shift state and selective-erase state are not modeled, and additional DEC save/restore semantics remain future compatibility work.
- Erase/edit/scroll operations implement xterm-style background-color erase (BCE): newly blank cells retain the current logical SGR background color, including indexed and direct RGB backgrounds, while foreground color and emphasis attributes are not fabricated onto blanks. SGR 49 restores default-background erasure. ED/EL, insert/delete character and line operations, scrolling/reverse-index blank rows, and the 1049 alternate-screen clear use this policy; host resize padding remains default-style because resize is a geometry operation rather than terminal erasure.
- DECAWM defaults enabled. When applications disable it with `CSI ? 7 l`, single-cell output at the right margin replaces the final cell without wrapping or scrolling. A two-cell Unicode character that arrives with only the final column available cannot be represented without violating the fixed-width grid, so the terminal stores U+FFFD in that final cell instead of creating an orphan wide-cell continuation or forcing a wrap. Re-enabling DECAWM restores delayed right-margin wrapping for subsequent output.
- Horizontal tabulation initializes the standard stops at columns 9, 17, 25, ... and honors HTS (`ESC H`), TBC current/default (`CSI g` / `CSI 0 g`), TBC clear-all (`CSI 3 g`), HT, and CHT against the active stop set. Stop storage is bounded to current terminal width. Resize preserves surviving stops and forgets truncated columns; pristine default tables gain default stops when widened, while a table that an application customized or cleared widens without fabricating new stops. RIS restores the default table. Tab-stop reporting remains unsupported.
- Unicode width comes from pinned generated Unicode 17 data with the default non-CJK ambiguous-width policy. Wide cells use an explicit continuation slot. The grid now preserves the release-critical bounded emoji sequence families exercised by tests—ZWJ emoji, emoji modifiers, regional-indicator flag pairs, keycaps, and VS15/VS16 presentation changes—and computes their final cell width with `unicode-width` string rules rather than advancing once per scalar. Sequence suffix storage is fixed at 15 scalars per cell; additional extending scalars are deterministically ignored once that bound is reached, while ordinary combining marks retain their existing three-mark limit. This is intentionally not a claim of complete UAX #29 extended-grapheme segmentation: uncommon grapheme classes and renderer-dependent shaping can still differ, and configurable ambiguous-width policy remains unsupported.
- Device/status negotiation is only partial. Primary DA and the currently implemented status/cursor reports are truthful, but many later DEC/xterm queries and modes are not implemented; applications that depend on them may still mis-detect the terminal.
- SGR support includes bold, italic, underline, inverse, the basic and bright 16-color ranges, the full 0-255 indexed palette, and direct RGB foreground/background colors. Strikethrough, blink/conceal, underline color/style, dim intensity, and colon-delimited extended-color forms are not yet represented.
- Keyboard input covers common character, control, navigation, editing, F1-F12 sequences, DECCKM normal/application cursor-key behavior for arrows plus Home/End, DECKPAM/DECKPNM application-keypad sequences when the host event source truthfully marks a key as keypad-origin, and xterm bracketed paste. The frontend requests Crossterm's escape-code disambiguation enhancement so supported hosts can expose keypad provenance and restores the host enhancement stack during cleanup. Hosts that do not provide keypad provenance retain ordinary key behavior rather than having keypad semantics fabricated. NumLock-marked keypad events also retain numeric behavior. Modifier-rich xterm/kitty keyboard protocols remain unsupported.
- Mouse input supports xterm event-selection modes 1000 (press/release), 1002 (button-event motion), and 1003 (any-event motion) when paired with SGR extended-coordinate mode 1006. Event-selection modes are represented as one fixed mutually exclusive state; SGR encoding is independent. Selecting unsupported mutually exclusive tracking or encoding protocols clears stale supported state rather than continuing to emit an encoding the child no longer selected, and RIS resets mouse negotiation to disabled. The frontend enables Crossterm host mouse capture only while a supported tracking mode plus 1006 is active, filters the broader host event stream back down to the child-requested semantics, encodes Shift/Alt/Ctrl and 1-based coordinates, treats wheel input as press-like events with no fabricated release, and disables host capture on mode reset or frontend cleanup. Crossterm documents platform differences in button identity and modified pointer gestures, so forwarded reports reflect host event provenance rather than invented precision. Legacy X10/UTF-8/urxvt mouse encodings, selection, and clipboard integration are not implemented.
- Unix PTY and Windows ConPTY builds/tests pass dedicated interactive frontend smoke paths in CI. The Unix path additionally validates a real `less` pager through the terminal-emulation and damage-rendering path. This still does not replace broader manual compatibility testing across terminal hosts, shells, editors, full-screen applications, SSH servers, tmux installations, and older supported OS versions.
- A concrete SSH endpoint is available through `terminal-cli --ssh TARGET`, but it deliberately delegates the protocol to an installed system `ssh` executable. Authentication, credentials/agents, host-key verification, `~/.ssh/config`, ProxyJump, algorithms, forwarding policy, and network lifecycle therefore follow the user's OpenSSH installation. The endpoint advertises remote + resize only; detach/persistence and authoritative remote scrollback are not provided. The SSH integration has deterministic construction/capability tests but CI does not require a public SSH server.
- A concrete tmux endpoint is available through `terminal-cli --tmux SESSION`, but it deliberately delegates multiplexing to an installed system `tmux` executable. It uses tmux's documented attach-or-create `new-session -A -s` path and feeds that client's raw PTY bytes through the normal terminal-emulation pipeline. The endpoint advertises local persistence + resize because tmux sessions live independently in the tmux server, but it does not advertise programmatic detach or authoritative scrollback. Interactive detach remains governed by the user's tmux prefix/key configuration, and CI validates direct argument construction/capability truth without requiring a long-running tmux server.
- TERM recognition is diagnostic only. Unknown values are deferred to the host terminfo database.
- Trusted Lua configuration is not sandboxed and is for user-owned configuration only.
- Third-party extension contracts define authorization, bounded delivery, and lifecycle isolation, but no language runtime, package manager, marketplace, or dynamic loader is embedded. Release regression coverage proves a full output inbox produces explicit critical backpressure, then host suspension/disconnection, while terminal feed progress continues independently.
- Transition instrumentation records samples but deliberately defines no product-level latency budget yet.
